## Evidence

The relay scenarios exercise the checked application and its on-disk records. Tool and filesystem tests evaluate real FluxR modules and Windows effects. The private Git fixture interoperates with the installed Git reference implementation. The first acceptance gate in the design requires a successful and applicable failure case for every registry ID. That full matrix is still open. A live Codex subscription walkthrough opened a fresh folder, read its preview command, requested the port alongside the command, accepted the revised answer and asked about the export format. The revised turn included the selected question and answer. The transcript retained one earlier answer and one accepted revision. Current native control tests cover automatic answer publication, exact follow-up context and keeping a draft when an answer arrives. They also cover returning from the folder picker to an addressed draft. A separate regression updates a request during a project read and checks that the revised request completes.

Relay staged and applied the chat routing and question-picker changes in its own registered project through two reviewed patch effects. The native controller regression opens one or two questions, moves them beyond the current history page, and checks the composer before and after accepting a newer answer. Expanding **Other questions** preserves the addressed draft. Selecting a question or starting a new topic changes its destination. During live verification, separate continuations for two effect status checks left three final answers held. After Relay patched its receipt handling, repeating the two checks produced one continuation with both completed receipts and one accepted final answer. The two earlier questions remained open.

## Reproduce

Run `pwsh -File .\Test-RelAI.ps1` from the checkout. The live subscription checks are opt-in through `pwsh -File .\Start-RelAI.ps1 -CheckProvider`. They verify an attached word and resume a question that requested an upload. The latter must read a unique README value from the selected project and return it without asking again. Offline tests use temporary data and make no inference calls. A live checkout review through the loopback API issued two file reads in one response. RelAI delivered both receipts in one continuation and returned the review in two foreground model turns. The batch integration tests also cover restart, concurrent callbacks, retries, and external-file scope. A second live exercise opened two questions, routed each answer to the chosen question and accepted one combined result. Both original questions closed with no duplicates or held actions.
