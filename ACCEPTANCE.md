# Acceptance status

The design is the product target. Each row gives the behavior covered by the current Windows integration suite and the boundaries of that evidence. The suite invokes checked FluxR exports, the loopback daemon, or the native primitive identified by the test.

| Design area | Implemented and tested | Remaining acceptance work |
|---|---|---|
| Native Windows interface | Dark native workspace, first-run folder selection, active-view navigation, docking and draft preservation, file picker/drop ingestion, explicit Unicode completion and definition editing, typed tool forms, graph filtering and comparison. Maximum-size graph comparisons and 100-card histories have bounded page sizes. The reusable Win32 host exercises control lifetime, focus, edit serials and layout with hidden native controls | Manual visual and screen-reader qualification on supported DPI configurations |
| Relay, model turns and attachments | Permanent project identity, prompt and attachment capture, submission-key conflicts, immutable turn retry, user acceptance, final delivery, one improvement session | All disposition combinations, cancellation during effects, verifier-backed criteria across every scope and fault-injection boundary |
| Routing and fan-outs | Separate human receipts for siblings, descendant review before an ancestor, restart while waiting on a named question, validation of review references | Mixed revision and replacement scenarios, all deadlock and wake cases, independent deterministic verification of every closure criterion |
| Local provider | Two real ChatGPT-authenticated Codex App Server turns using an exact model and effort. The foreground turn read the attached word. After independent acceptance, one final delivery and one no-change improvement were recorded | Live sibling routing and review, and comparison against a single-worker baseline |
| Other providers | Checked Anthropic Messages and Qwen Chat Completions request and response adapters | Endpoint behavior intentionally untested at the owner's request |
| Checked tools and improvement | Compiler admission, native/host rejection, traps and subsequent VM usability, immutable versions, independent counterexamples, qualification and retirement. A corrected Markdown link checker runs against retained snapshots without a model call. Defect publication requires an independent failing baseline and passing correction. Default promotion preserves human wording and checks the stable capability | Dependent batch execution, broader contract families and measured adoption costs |
| Files, caches and graph | SHA-256 artifacts, retained snapshot bytes, bounded line and byte reads, glob pagination, fresh host reads, project isolation, Windows watcher, in-memory LRU and snapshot reconciliation | Retained Rust module edges and cross-file FluxR call edges include byte spans and stale-source evidence. Semantic lookup returns ranked retained passages. Block-level I/O, shared-job cancellation, single-flight accounting and remaining graph interaction scenarios are pending |
| Protected writes | Real NTFS TxF commits, stale expected-state rejection, copy/move/remove, atomic multi-file rollback, private paths and hard-link rejection, patch staging, exact grants and recovery | Packed refs and linked-worktree checkout guards, complete erasure and replay, additional crash boundaries |
| Git and source analysis | In-process objects, history, blame, local status, selected staging and commits, branch operations and private managed linked worktrees. A real loopback Git server exercises HTTPS push, fetch, stale and backwards updates. Embedded Rust and FluxR syntax analysis returns byte spans | Workspace-wide symbol resolution and remaining Git recovery boundaries. Inert package drafts, third-dictionary denial and old tool bindings are tested | Remaining UI navigation, aliases, recall conflicts and package update/rollback scenarios |
| Document and structured data tools | DOCX, PDF text extraction, XLSX cells and formulas, notebooks, CSV and bounded ZIP processing. Archive expansion limits and malformed input are exercised | Full catalog input, output, resource-budget and access contracts |

## Evidence

The relay scenarios exercise the checked application and its on-disk records. Tool and filesystem tests evaluate real FluxR modules and Windows effects. The private Git fixture interoperates with the installed Git reference implementation. The first acceptance gate in the design requires a successful and applicable failure case for every registry ID. That full matrix is still open. ## Reproduce

Run `pwsh -File .\Test-RelAI.ps1` from the checkout. The live subscription test is opt-in through `pwsh -File .\Start-RelAI.ps1 -CheckProvider`. It records the observed number of attempts and checks the word that came from the attachment. Offline tests use temporary data and make no inference calls.
